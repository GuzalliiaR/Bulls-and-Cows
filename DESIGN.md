# Design Document — Bulls and Cows

## 1. Структуры данных и алгоритмы

### Состояние игры (`src/core/gameState.ts`)

`GameState` — неизменяемый объект с полями `status`, `settings`, `secret`,
`history`, `startedAt`, `finishedAt`. Все поля объявлены `readonly`, массивы —
`readonly string[]` / `readonly AttemptEntry[]`, поэтому любая попытка мутации
(`state.history.push(...)`) является ошибкой компиляции.

Почему объект, а не класс: задание требует функциональный стиль
(`task.md:69`), а состояние — это данные, не поведение. Поведение живёт
в отдельных чистых функциях-редьюсерах: `startGame`, `makeAttempt`, `resetGame`.

История попыток — массив `AttemptEntry[]` в порядке добавления. Массив выбран
вместо `Map` или `Set`, потому что: (а) порядок значим для отображения,
(б) дубликаты отсекаются на входе (`makeAttempt`), поэтому ключей не нужно,
(в) иммутабельное добавление — одна строка `[...history, entry]`.

### `evaluateGuess` (`src/core/evaluateGuess.ts`)

Алгоритм в два прохода:

1. Нормализация: `secret` и `guess` приводятся к нижнему регистру один раз.
2. Bulls: позиционное сравнение, подсчёт через `filter(...).length`.
3. Остатки: оба массива фильтруются по индексам, где bull уже засчитан.
4. Cows: цифры из остатка `guess`, входящие в остаток `secret`, через `Set`.

Ключевое: cows считаются от **остатков**, а не от полных массивов — это
защищает от двойного счёта цифры, которая уже стала bull.

### `countPossibleSecrets` (`src/core/countPossibleSecrets.ts`)

Число размещений без повторений: `P(base, length) = base! / (base − length)!`,
что эквивалентно убывающему произведению `base · (base−1) · … · (base−length+1)`.

Реализация рекуррентная:
`P(base, length) = base · P(base−1, length−1)`, база `P(base, 0) = 1`,
`P(base, length) = 0` при `length > base`.

Мемоизация через HOF `memoize` (`src/core/memoize.ts`): кэш живёт в замыкании
инстанса, ключ — сериализованные аргументы. Рекурсия идёт через мемоизированную
обёртку, поэтому в кэш попадает вся цепочка промежуточных значений, а не только
верхний вызов.

## 2. Сложность (Big O)

| Функция                                | Время                                  | Память           | Обоснование                                                                                |
| -------------------------------------- | -------------------------------------- | ---------------- | ------------------------------------------------------------------------------------------ |
| `generateSecret(length, base, random)` | O(length · base)                       | O(base + length) | на каждом из `length` шагов фильтруется пул размером `≤ base`                              |
| `evaluateGuess(secret, guess)`         | O(n²)                                  | O(n)             | `includes` внутри `filter` даёт вложенный поиск; `n ≤ 6`, замена на `Set` не даёт выигрыша |
| `isValidGuess(guess, length, base)`    | O(n)                                   | O(n)             | один проход `every` по цифрам + построение `Set` из `n` символов                           |
| `countPossibleSecrets(length, base)`   | O(length) первый вызов, O(1) повторный | O(length)        | ровно `length + 1` рекурсивных вызовов; кэш хранит всю цепочку                             |

## 3. Принципы чистого кода

### Чистые функции и функциональный стиль

- `src/core/generateSecret.ts` — принимает источник случайности параметром
  (`random = Math.random`), поэтому тестируется детерминированно.
- `src/core/gameState.ts: makeAttempt` — редьюсер: принимает состояние,
  возвращает новое, использует `[...history, entry]` вместо `push`.
- `src/core/evaluateGuess.ts` — вычисление через `reduce`/`filter`, без ручных
  циклов со счётчиками.

### DRY (Don't Repeat Yourself)

- `src/core/memoize.ts` — общий HOF, а не копия логики кэша в каждой функции.
- `src/core/createDigitValidator.ts` — единственное место, где известно правило
  «допустимые цифры для base»; используется в `isValidGuess` и в UI.
